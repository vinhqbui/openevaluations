# openevaluations

Open, longitudinal evaluations of coding-agent CLIs, published at **https://openevaluations.si**.

- **Tracker.** The same small task sets, meant to run weekly (the schedule is off for now) against Claude Code and other agent CLIs.
  Every run records the CLI's own version, so a release that moves the pass rate or the number of
  tool calls shows up as a flagged point.
- **Handoff benchmark.** Agent A works on a task and stops; agent B takes over. Each channel
  starts from the same frozen A: repo only, A's trace, A's `NOTES.md`, or A's structured records
  (via [Scholion](https://github.com/vinhqbui/scholion)). Only the channel differs.
- **Ledger.** What a merged, reviewed feature cost when Scholion Cloud worked its own backlog, and
  how often a human stepped in, week by week ([`docs/PREREG-ledger.md`](docs/PREREG-ledger.md)).
  Reported, never claimed, and not a tracker series.
- **Open data.** One JSON Lines file per run in [`runs/`](runs/), schema [oe/1](schema/), CC BY 4.0.

Agents run through [Harbor](https://github.com/harbor-framework/harbor) (Apache-2.0), one fresh
container per trial, with hidden tests deciding acceptance.

## Weekly tracker legs

By hand for now (`gh workflow run tracker.yml`; the weekly schedule is off), `tallyho-cold`, 3 attempts per task, all on
DeepSeek Flash, each CLI at its newest release that day:

| Leg | CLI | How it reaches DeepSeek | Harbor agent |
|---|---|---|---|
| `claude-code-cold` | Claude Code | Anthropic-compatible API (`ANTHROPIC_BASE_URL`) | `claude-code` |
| `claude-code-av` | Claude Code on Scholion `av` | the same, plus the av hooks and daemon | `oe_agents.claude_code_av:ClaudeCodeAv` |
| `opencode-cold` | OpenCode | its `deepseek` provider | `opencode` |
| `codex-cold` | OpenAI Codex CLI | a custom model provider in `config.toml`, DeepSeek's Responses API | `oe_agents.codex_deepseek:CodexDeepSeek` |

Gemini CLI is not a leg: it speaks only the Gemini API (`GOOGLE_GEMINI_BASE_URL` moves the
endpoint, not the protocol), so on DeepSeek it would need a translating proxy in between.

## Quick start

```bash
uv sync                                   # tools only: validate, import, stats, site
uv run pytest -q
uv run oe validate                        # every runs/*.jsonl against schema/
uv run oe stats runs/scholion-2026-10-31-relay-image.jsonl
uv run oe site && python -m http.server -d site 8000   # http://localhost:8000

uv sync --extra run                       # + Harbor; needs Docker
uv run harbor run -p datasets/tallyho-cold -a oracle -o jobs   # every reward 1
uv run harbor run -p datasets/tallyho-cold -a claude-code -m anthropic/claude-haiku-5-5 -k 3 -o jobs
PYTHONPATH=agents uv run harbor run -p datasets/tallyho-cold -a oe_agents.codex_deepseek:CodexDeepSeek   -m deepseek/deepseek-flash -k 3 -o jobs --agent-setup-timeout-multiplier 2   # needs DEEPSEEK_API_KEY
uv run oe import-harbor jobs/<job> --dataset tallyho-cold && uv run oe detect && uv run oe site

# the ledger: reports.json is one repo's week (Monday to Sunday) from the Scholion Cloud daemon,
# GET /v1/ee/reports?repo=scholion&from=2026-11-09&to=2026-11-15 (admin token; see the foundry runbook)
uv run oe import-reports reports.json && uv run oe site
```

## Layout

| Path | What |
|---|---|
| `schema/` | `run.schema.json`, `session.schema.json` (oe/1) and the field rules |
| `runs/` | published runs, `<run-id>.jsonl`: line 1 the run, then one line per session |
| `datasets/` | Harbor task sets; `tallyho-cold/` (the tracker's four tasks) and `tallyho-more/` (two more, kept out of the tracker) are generated by `tools/gen/tallyho.py` from `_shared/`, `handoff-interrupt/` by `tools/gen/handoff.py` from the frozen A's in `_shared/handoff/` |
| `tools/oe/` | the `oe` CLI: `validate`, `import-scholion`, `import-harbor`, `import-reports`, `stats`, `detect`, `site`, `budget`, `freeze`, `rewards` |
| `agents/` | custom Harbor agents: `oe_agents.claude_code_av:ClaudeCodeAv`, Claude Code on the Scholion framework, `oe_agents.codex_deepseek:CodexDeepSeek`, Codex CLI on DeepSeek, and `oe_agents.handoff_a:HandoffA`, the handoff predecessor (`PYTHONPATH=agents`) |
| `site/` | the static site; `site/data/` is generated by `oe site` and checked in CI |
| `docs/` | methodology and the pre-registration template |

## Contributing a run

Run a dataset with Harbor, import it with `oe import-harbor`, check `oe validate`, and open a
pull request adding the file under `runs/`. State the agent, model and any arguments in the PR.
See `docs/methodology.md` for what counts as a valid session.
