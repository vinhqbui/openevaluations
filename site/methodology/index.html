Methodology

What is run, what is measured, and which claims the numbers can carry.

Running

Agents run through Harbor, the Terminal-Bench team's open harness. Each trial gets a fresh Docker container. The task's repository is collapsed to a single commit, so the fix cannot be read from history. The agent's own CLI runs headless with the goal as its prompt. When it stops, hidden tests are copied in and decide the reward. The weekly tracker does not pin the CLI version, because measuring version drift is the point. Each run records the version the CLI reports for itself.

Scholion is evaluated as an arm, through a Harbor agent that wraps Claude Code with Scholion's daemon and hooks. Plain Claude Code, Codex and other CLIs run through Harbor's own adapters.

What a session records

  • Acceptance. The hidden tests pass, which is a reward of 1.
  • Cost. Every cost has a source: measured by the CLI, estimated from token counts, capped when a session hit its spending cap, or unavailable.
  • Tokens. Billed tokens are input plus cache writes plus output, with cache reads excluded.
  • Effort. LLM calls, turns and tool calls, taken from the trajectory.
  • Repeated dead ends. For handoff tasks, a pattern matches the known wrong edit in the agent's writes.
  • Wall time for the agent's own execution.

Results format: oe/1

A run is a JSON Lines file. Line 1 is the run: dataset and revision, agent name and version, model, arm, harness versions, machine, budget, pre-registration and flags. Every following line is one session. Schemas: run.schema.json, session.schema.json. A run on a private task set publishes only its run line and an aggregate. Its sessions and task names stay private.

Statistics

  • Acceptance is reported with a Wilson 95% interval.
  • Cost per accepted task is total spend over accepted sessions, with a session bootstrap.
  • Arm and channel deltas are paired by task: the mean over tasks of arm ÷ control − 1, with a task-stratified bootstrap, 2000 resamples, fixed seed. Truncated sessions are skipped.
  • No significance claim is made below 30 valid sessions per cell.
  • Pre-registration. Paid comparison runs write their question, arms, model, budget and decision rule in a PREREG file first. Anything added afterwards is labelled exploratory.

Change detection

Each run is compared with the four before it in the same series, meaning the same dataset, agent, model and arm. A run is flagged degraded when its Wilson upper bound is more than 15 points under the baseline acceptance rate. It is flagged tool calls up when its median tool calls exceed 1.5× the baseline's. A flagged series that comes back inside both thresholds is marked recovered. Fewer than 12 valid sessions gives low n and no other flag.

Handoff benchmark

Agent A works on a task and stops; agent B takes over. In the interrupt family, A runs once per task (an invalid A is re-run once, then the task is dropped) and is frozen: its working tree as a patch, its transcript, its NOTES.md and its Scholion records, with the sha256 of each, which the generator checks, so an edit to a frozen file is caught. Each channel is then generated as its own task from that one A. Every image holds the same tree, A's changes applied and uncommitted. repo-only adds nothing, trace adds the transcript and notes adds the notes file. Before any successor runs, a leak check looks for markers of the hidden tests (the test file's name, its test names and every line of 20 or more characters not already in the base tree) in every artifact, a person reads each frozen A's notes and trace, and each generated task must score 0 with an agent that does nothing (A had not already solved it) and 1 with the reference fix applied after A's work is reset. Successors are paired by task against repo-only. The interrupt family's rules are pre-registered in PREREG-handoff-interrupt.md.

Threats to validity

  • Small task sets. Weekly sets are small so they stay cheap. Treat them as a regression tracker, not a capability ranking.
  • Author bias. The task sets were written alongside Scholion, which is one of the evaluated arms. Public tasks, published prompts and pre-registration are the guard.
  • Contamination. The task repositories were written for benchmarking in 2026 and are unlikely to be in training data. Their patches are public now, though.
  • Harness effects. The same model scores differently under different harnesses. Every row names its harness, and results are never pooled across harnesses.
