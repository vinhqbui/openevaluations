Coding agents, measured in the open.

The same tasks, run on a schedule against each new CLI version, with every session's raw row published. Also a benchmark for the moment one agent hands a task to another.

Why this exists

Agents change under you

A coding agent is a model plus a harness, and the harness ships weekly. A CLI release can move pass rates and tool calls even when the model stays the same. Public trackers of this exist, but their data stays closed.

Handoffs are not measured

Benchmarks score one agent on one uninterrupted task. Real work is picked up from someone else. The protocol for measuring that exists in a paper, but no code was released. Here it is runnable.

LLM-app evals are a different job

Frameworks such as DeepEval score the LLM application you build, from its traces. They do not run Claude Code or Codex on a repository task and check the result with hidden tests. That is what this site does.

How it works

Fixed tasks, hidden tests

Each task is a repository at a base commit, a goal, and hidden tests that decide acceptance. The tasks are in the Harbor format, so any of its 40+ agent adapters can run them.

An open results format

One JSON line per session: reward, cost and where the cost came from, tokens, LLM calls, tool calls, wall time, and the agent's own version string. Schema oe/1.

Honest statistics

Wilson intervals on acceptance, paired bootstraps for arm deltas, pre-registration before paid runs, and no significance claim below 30 sessions per cell.

Status. The data so far is the 18 runs that seeded this project: Claude Code on two small Python task sets, recorded by Scholion's own benchmark harness. Weekly Harbor runs of Claude Code and a second agent start next. Scholion is one evaluated arm here, not the subject.
