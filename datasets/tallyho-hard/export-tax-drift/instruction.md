One Python process runs tallyho for several shops. For each shop it calls `load_config` on that shop's file and quotes the shop's orders with `quote_order(order, taxes=cfg.taxes)`; at the end it writes a CSV of all the orders with `orders_to_csv`. Since the latest release the numbers drift: once one shop's config has a `[tax]` section, the shops loaded after it are taxed at its rates for regions their own config never mentions, and the CSV's totals stop using the standard rates.

Fix it. A quote made with a config's `taxes` uses the rates from that config's `[tax]` section and the shipped default rates for every other region. A quote or CSV export made without a tax table always uses the shipped defaults, the ones `default_tax_table()` returns in a fresh process. Neither may depend on which configs were loaded, or which tax tables were changed in code, earlier in the same process.
